使う前に知っておきたいこと

コードはそのままでは動かないことがあります

標本のコードは「こういうことができる」を示す見本です。次の理由で、エラーになったり思いどおりに動かなかったりします。

  • 「フォルダID」「シートID」やメールアドレスを、自分のものに書き換えていない
  • シート名・列の並び・見出し行の有無が、コードの前提と違う
  • 日付が文字として入っている、空の行があるなど、データの形が違う
  • 会社のGoogle Workspaceで、管理者がGASや外部への接続を制限している
  • Googleや外部サービス（LINE、天気APIなど）の仕様が変わった

エラーが出たら、画面下の「実行ログ」のメッセージで検索するか、作成をご依頼ください。

まずはテスト用のコピーで試す

本番のデータでいきなり実行しないでください。上書きや削除は「元に戻す」が効かないことがあります。ファイルをコピーして、そちらで動きを確かめましょう。

メールは自分宛てで試す

一斉送信などは、まず宛先を全部自分にして文面を確認してください。送ったメールは取り消せません。不安なら「下書きをまとめて作成」の標本が安心です。

初回の「承認」画面について

初めて実行すると「このアプリはGoogleで確認されていません」と表示されることがあります。自分で貼り付けたコードなら「詳細」から進めば実行できます。中身のわからないコードは許可しないでください。メールやファイルを読む権限を渡すことになります。

パスワードや鍵をコードに書かない

LINEのアクセストークンやWebhookのURLは、「プロジェクトの設定」→「スクリプト プロパティ」に保存します。

const token = PropertiesService
  .getScriptProperties().getProperty('LINE_TOKEN');
自動実行の落とし穴
  • 時間指定のトリガーは「8時〜9時の間」のように幅があり、ちょうどの時刻には動きません。
  • 名前だけで動く onEdit では、メール送信など許可が必要な処理はできません。「トリガー」画面から設定します。
  • onEdit は人が手で編集したときだけ動きます。数式の再計算や別のスクリプトによる変更では動きません。
  • トリガーを作るコードを何度も実行すると、同じトリガーが増えて二重に動きます。
タイムゾーンと引き継ぎ

「プロジェクトの設定」でタイムゾーンが「(GMT+09:00) 東京」か確認してください。また、トリガーは設定した人のアカウントで動くため、退職やアカウント削除で止まります。誰が何を設定したか記録しておきましょう。
