# ラクガス図鑑

Googleの「めんどう」を、GAS（Google Apps Script）でラクにする56の方法を集めた図鑑サイトです（うち12種は、AI・外部API・承認の流れなどを組み合わせる「応用」）。
動くデモ・コード例・作成依頼フォーム（3,000円〜）つき。

## 構成

```
GitHub Pages（このリポジトリのHTML）
   │  依頼フォームを送信
   ▼
GAS ウェブアプリ（gas/コード.gs）
   ├─ スプレッドシート「ラクガス図鑑 依頼一覧」に記録
   ├─ あなたのGmailに「新しい依頼」をメール
   └─ サイトの使われ方（匿名）を「アクセスログ」シートに記録
        │
        ▼
管理者ダッシュボード（GAS・あなたのGoogleアカウントでのみ開ける）
```

| ファイル | 役割 |
|---|---|
| `index.html` | ページ本体 |
| `assets/style.css` | デザイン |
| `assets/app.js` | 画面の動き（図鑑・観察窓・依頼フォーム） |
| `assets/data.js` | 56種の標本（No.045〜056は応用。`adv: true` と「応用のポイント」`tips` つき）と観察窓の場面データ |
| `assets/config.js` | **GASのURLを書く場所** |
| `index.html` の `#furoku` | 付録「不動産業務のGAS化判定」（62業務の判定・最初に着手したい12業務・全件の表） |
| `gas/コード.gs` | 依頼の受付窓口（GASに貼り付けるコード） |
| `gas/dashboard.html` | 管理者ダッシュボードの画面（GASに「dashboard」という名前で追加） |
| `gas/threads.gs` | Threads への予約投稿（承認したものだけ）と成績の記録（GASに「threads」という名前で追加） |

## 手順1：GASの受付窓口をつくる（約10分）

依頼を記録するスプレッドシート「**ラクガス図鑑 依頼一覧**」は、あなたのGoogleドライブに作成済みです。

1. Googleドライブで「ラクガス図鑑 依頼一覧」を開く。
2. メニューの「拡張機能」→「Apps Script」を選ぶ。
3. 最初からあるコードを消し、`gas/コード.gs` の中身をすべて貼り付けて保存（Ctrl + S）。
4. 上部の関数の選択欄で **`setup`** を選んで「実行」。
   - 許可を求められたら、自分のアカウントを選んで許可します。
   - 「Googleで確認されていません」と出たら「詳細」→「（プロジェクト名）に移動」。
   - 「受付窓口の準備ができました」というメールが届けば成功です。表の見出しと「状態」のプルダウンも整います。
5. 右上の「デプロイ」→「新しいデプロイ」→ 歯車から「ウェブアプリ」を選び、次のように設定して「デプロイ」。
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**全員**
6. 表示された「ウェブアプリのURL」（`https://script.google.com/macros/s/…/exec`）をコピー。

> 通知先を変えたいときは、コードの先頭の `NOTIFY_TO` にメールアドレスを書きます（空ならGASを動かすアカウント宛て）。

## 手順2：サイトにGASのURLを書く

`assets/config.js` を開き、手順1-6のURLを貼り付けます。

```js
window.RAKUGAS_CONFIG = {
  gasUrl: 'https://script.google.com/macros/s/xxxxxxxx/exec'
};
```

GitHubの画面上で直接編集できます（ファイルを開いて鉛筆マーク →「Commit changes」）。

## 手順4：管理者ダッシュボードを使えるようにする（約5分）

サイトのアクセス状況と依頼の状況を、1画面で見られます。あなたのGoogleアカウントでログインしたときだけ開ける設定にします。

1. 手順1のApps Scriptで、`コード.gs` を最新の `gas/コード.gs` に置き換えて保存。
2. 左の「ファイル」の＋ →「HTML」を選び、名前を **`dashboard`** にする（`.html` は自動で付きます）。中身を `gas/dashboard.html` に置き換えて保存。
3. 今のウェブアプリを更新：「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「バージョン：新バージョン」→「デプロイ」。（URLは変わりません。ここからサイトのアクセス記録が始まります）
4. ダッシュボード用に、もう1つデプロイを作る：「デプロイ」→「新しいデプロイ」→「ウェブアプリ」
   - 説明：ダッシュボード
   - 実行するユーザー：**自分**
   - アクセスできるユーザー：**自分のみ**
5. 表示されたURLの末尾に `?view=admin` を付けて開く（例：`https://script.google.com/macros/s/…/exec?view=admin`）。ブックマークしておくと便利です。

> 「アクセスログ」シートは、最初の記録が届いたときに自動で作られます。

### 期間と集計の単位

- 上部の見出しタブで「**依頼と売上**」と「**アクセス**」の画面を切り替えます（キーボードの←→でも切り替えられます）。期間と単位は、どちらの画面にも共通でかかります。タブには、もう一方の画面の主な数字も小さく出ます。
- 上部のボタンで「直近7日・直近30日・今月・先月・直近90日・今年・昨年」を選ぶか、開始日と終了日を指定します。
- 集計の単位は **日・週（月曜はじまり）・月・年** から選べます。「日」は400日まで、期間全体は10年までです。
- 「◯ごとの集計」の表に、期間ごとの訪問者・依頼・契約・継続依頼・保留・失注・成約率・売上・平均単価が並びます（先頭は合計）。

### 「集客と導線」タブ

- **カスタマージャーニー**：サイトを訪れた → 標本を開いた → 料金を見た → 依頼フォームを開いた → 依頼が届いた → 成約した → 継続依頼、の各段階の数と、次へ進んだ割合。いちばん落ちている段階を赤く示します。
- **流入元・記事ごとの成果**：noteの記事ごと（`utm_campaign`）に、セッション・標本・料金・フォーム・依頼・成約・売上を並べます。依頼は、依頼した人が最後に来た流入元（30日以内）で数えます。依頼一覧の「流入元」列にも記録されます。
- **訪問が多い曜日と時間**：すべて／note経由で切り替え。noteに投稿する時間の手がかりにします。

### 見られること

- 依頼と売上：依頼数、成約（契約＋継続依頼）、成約率、売上、平均単価（中央値も）、見込み額（保留＋未確定）
- 商談の結果の推移、売上の推移、依頼単価の内訳（種類ごとの件数・売上・平均・最小・最大）、この期間の依頼
- 訪問者・セッション・ページビュー・平均滞在時間・依頼フォームを開いた回数・依頼への転換率
- 訪問の推移
- 依頼までの流れ（訪問 → 標本を開いた → 依頼フォームを開いた → 送信）と、各段階で進んだ割合
- 依頼の状況（受付・対応中・完了）と最近の依頼
- よく開かれた標本、よく検索された言葉、**見つからなかった検索**（新しい標本や依頼の種）
- どこから来たか、依頼ボタンが押された場所、観察窓で選ばれた場面、端末、どこまで読まれたか、よく使われた絞り込み

### 知っておいてほしいこと

- **自分のアクセスを数えない**：自分のブラウザで一度だけ `https://futurefoundry19840305.github.io/rakugas-zukan/?notrack=1` を開くと、そのブラウザからは記録されなくなります（元に戻すときは `?notrack=0`）。
- **noteからの訪問を分けて数える**：記事に載せるリンクを `…/rakugas-zukan/?utm_source=note` にすると、「どこから来たか」に note と表示されます。
- **記録している内容**：ランダムな訪問者ID、使われた機能（標本を開いた、検索した言葉など）、端末の種類と画面幅だけです。名前・メールアドレス・IPアドレスは記録しません。ブラウザで「トラッキング拒否」を有効にしている人は記録しません。サイトのフッターにもその旨を書いています。
- **ログの量**：1回の訪問で10〜20行ほど増えます。集計は直近90日分を使います。行が数万を超えて重くなったら、古い行を別のシートに移すか削除してください。
- **管理者以外は見られない**：「自分のみ」のデプロイは、あなたのGoogleアカウントでログインしないと開けません。公開用のURLに `?view=admin` を付けて開かれても、あなた以外にはデータを表示しません。

## note下書きのルーティン（週2回・自動）

毎週**月曜と木曜の朝7時40分ごろ**、Claudeの定期タスクがnote用の記事の下書きを1本作ります。公開はしません。あなたが確認してから、noteに貼り付けて投稿します。

1. GASの `updateTopics` が毎朝6時ごろ、Googleドキュメント「**ラクガス図鑑 記事のネタ（自動更新）**」に、見つからなかった検索・よく開かれた標本・依頼で多い「自動化したいこと」などを書き出します（名前・連絡先は書きません）。`setup` を実行すると、この毎朝の更新が自動で設定されます。
2. 定期タスクが、そのドキュメントと図鑑の標本データを読み、**まだ書いていない業務を1つ**選びます。データがまだないうちは、時間削減の大きい標本から順に選びます。
3. 課題に寄り添う書き方で下書きを作り、Googleドライブの「**ラクガス図鑑 note下書き**」フォルダに「【下書き】日付 テーマ」という名前で保存し、スマホに通知します。
4. 下書きの先頭に「公開前チェック」（コードを試したか・数字の確認・タイトル案・ハッシュタグ案）があります。確認したら、noteに貼り付けて投稿してください。
5. 投稿したら、ファイル名の【下書き】を【公開済み】に変えておくと、記録として分かりやすくなります（同じテーマは選ばれません）。

記事のリンクには `?utm_source=note&utm_campaign=記事ごとの名前` が付くので、どの記事から来たかをダッシュボードの「どこから来たか」で確認できます。

## Threads への予約投稿（承認したものだけ）

毎週月曜の朝、Claudeの定期タスクが翌日からの1週間分（5本）の投稿文を作り、Googleドライブ「ラクガス図鑑 Threads下書き」に置きます。GASが「依頼一覧」の「Threads投稿」シートに取り込むので、**内容を確認して「承認」にチェックを入れたものだけ**が、予定の時刻に Threads の公式APIで投稿されます。

- 承認しないまま予定時刻を3時間過ぎた投稿は「見送り（未承認）」になり、投稿されません。
- 投稿ごとのビュー・いいね・返信・リポストを毎朝記録し、「記事のネタと数字」に時間帯ごとのビューをまとめます。定期タスクがそれを見て、次の週の曜日と時間を決めます。
- リンクには `?utm_source=threads&utm_campaign=投稿ID` が付き、ダッシュボードの「流入元・記事ごとの成果」に投稿ごとに出ます。
- アクセストークンは毎週日曜に自動で期限を延ばします。延ばせなかったときはメールで知らせます。

準備
1. Meta for Developers でアプリを作り、ユースケース「Threads API にアクセス」を選ぶ。権限 `threads_basic`・`threads_content_publish`・`threads_manage_insights` を追加する。
2. アプリの「役割」で自分の Threads アカウントを「Threadsテスター」に追加し、Threads アプリの「設定」→「アカウント」→「ウェブサイトのアクセス許可」で招待を承認する。
3. アプリの「ユーザートークン生成ツール」で長期アクセストークンを作る。
4. Apps Script の「プロジェクトの設定」→「スクリプト プロパティ」に、名前 `THREADS_TOKEN`、値にトークンを保存する（トークンはチャットやシートに貼らない）。
5. Apps Script に新しいスクリプトファイル `threads` を作って `gas/threads.gs` を貼り、`コード.gs` も最新に置き換えて保存する。
6. 関数 `setupThreads` を実行して許可する。実行ログに「@ユーザー名 として投稿します」と出れば完了。

## 商談と金額の管理（依頼一覧）

`setup` を実行すると、依頼一覧に3つの列が加わります（以前からの行は「商談」が「未確定」になります）。

| 列 | 入れるもの |
|---|---|
| 商談 | 未確定・契約・継続依頼・保留・失注 から選ぶ |
| 金額（円） | 見積もり・契約の金額。**単発の依頼には3,000円が最初から入る**ので、決まった金額に書き換えます。要相談の依頼は空欄のままでもかまいません（平均単価には含めません）。継続依頼は**月額**を入れます。 |
| 確定日 | 商談を「契約」「継続依頼」「失注」にすると自動で入ります。日付は手で直せます。 |

- **数え方**：依頼数・保留・未確定は「受付日」、契約・継続依頼・失注・売上は「確定日」で、その期間に数えます。
- **成約率**：（契約＋継続依頼）÷（契約＋継続依頼＋失注）。保留と未確定は分母に入れません。
- **売上**：契約と継続依頼のうち、金額が入っているものの合計です。継続依頼は確定した月に1か月分を計上します（毎月の売上として積み上げる仕組みにはしていません）。
- 「状態」（受付・対応中・完了）は依頼者に見える進み具合、「商談」はあなただけが見る結果です。別々に管理します。

## 依頼の管理

- **通知メール**に「返信」すると、依頼者の連絡先がメールアドレスなら、そのまま依頼者に返せます。
- **進み具合**は、スプレッドシートの「状態」列（受付・対応中・完了）をプルダウンで変えるだけです。依頼者は、同じブラウザでサイトの「あなたの依頼」を開くと確認できます。
- 「メモ」列は自由に使えます（サイトには表示されません）。

## GASのコードを直したとき

「デプロイ」→「デプロイを管理」→ 鉛筆マーク →「バージョン：新バージョン」→「デプロイ」。URLは変わらないので、`config.js` を直す必要はありません。
